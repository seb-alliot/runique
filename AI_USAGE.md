# Why the use of AI?

I have been turned down several times on platforms for sharing Rust projects because of my use of AI.

So I find myself having to justify my choices, in this era where you have the purists on one side, the vibe coders, and people like me who use it somewhere in between.

## Why the documentation is written with an AI

I am alone on Runique. No team, and no contributor for now, and probably never, given how strongly Rust developers are set against AI.

The project has become too big for one person to write the code and also keep the documentation up to date. It is about 220 pages, 110 in French and 110 in English, and I do not speak English.

So I made a choice, and I stand by it.

## What I write myself

The framework code. Proc-macros are the exception: they are not fully within my reach yet, so I write them with the help of the AI.

The design choices are mine.

## What I hand to the AI

The documentation, the comments in the code and the tests.

Without that, the project would take fifteen years, twelve of them for the documentation and the comments. The code is not what takes the longest to write.

## How I check

I review what is generated before publishing it, and the documentation is kept up to date with the source code.

The English version is made by the AI from the French one. I cannot review it myself.

## Why do I stand by AI for the documentation?

I prefer a faithful documentation that you can rely on over a documentation where you have to guess what is missing. That is my opinion, and I understand that not everyone shares it.

## If you find a mistake

A mistake in the documentation is a bug like any other: open an issue.

If you want to rewrite a page by hand, the contribution is welcome.
