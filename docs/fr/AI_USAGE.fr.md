# Pourquoi l'usage de l'IA ?

J'ai été plusieurs fois refusé sur des plateformes de partage de projets en Rust à cause de mon usage de l'IA.

Je me vois donc dans l'obligation de justifier mes choix en cette ère où on a d'un côté les puristes, les vibe codeurs et ceux comme moi qui l'utilisent entre deux.

## Pourquoi la documentation est écrite avec une IA

Je suis seul sur Runique. Pas d'équipe, et pas de contributeur pour l'instant, et sûrement jamais vu l'engouement anti-IA des développeurs en Rust.

Le projet est devenu trop gros pour qu'une seule personne écrive le code et tienne en plus la documentation à jour. Elle fait environ 220 pages, 110 en français et 110 en anglais, et je ne parle pas anglais.

J'ai donc fait un choix, et je l'assume.

## Ce que j'écris moi-même

Le code du framework. Les proc-macros font exception : elles ne sont pas encore entièrement à ma portée, je les écris avec l'aide de l'IA.

Les choix de conception sont les miens.

## Ce que je confie à l'IA

La documentation, les commentaires dans le code et les tests.

Sans ça, le projet prendrait quinze ans, dont douze pour la documentation et les commentaires. Le code n'est pas ce qui est le plus long à écrire.

## Comment je vérifie

Je relis ce qui est généré avant de le publier, et la documentation est tenue à jour par rapport au code source.

La version anglaise est faite par l'IA à partir du français. Je ne peux pas la relire moi-même.

## Pourquoi j'assume l'IA sur la documentation ?

Je préfère une documentation fidèle, sur laquelle on peut s'appuyer, à une documentation où il faut deviner ce qui manque. C'est mon avis, et je comprends qu'on ne le partage pas.

## Si tu trouves une erreur

Une erreur dans la documentation est un bug comme un autre : ouvre une issue.

Si tu veux réécrire une page à la main, la contribution est la bienvenue.
