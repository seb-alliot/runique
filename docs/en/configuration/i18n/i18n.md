# Internationalisation (i18n)

Runique includes a lightweight i18n system with no external dependencies.
Translations are embedded at compile time as JSON files, and the active language is a global state that can be changed at runtime.

---

## Supported languages

| `Lang` variant | Code | Recognised locale examples |
| --- | --- | --- |
| `Lang::Fr` | `fr` | `fr`, `fr-FR`, `fr-CA`, `fr-BE`, `fr-CH` |
| `Lang::En` | `en` | `en`, `en-US`, `en-GB`, `en-CA` |
| `Lang::De` | `de` | `de`, `de-DE`, `de-AT`, `de-CH` |
| `Lang::Es` | `es` | `es`, `es-ES`, `es-MX`, `es-AR`, `es-CO`, `es-CL` |
| `Lang::It` | `it` | `it`, `it-IT`, `it-CH` |
| `Lang::Pt` | `pt` | `pt`, `pt-PT`, `pt-BR` |
| `Lang::Ja` | `ja` | `ja`, `ja-JP` |
| `Lang::Zh` | `zh` | `zh`, `zh-CN`, `zh-TW`, `zh-HK` |
| `Lang::Ru` | `ru` | `ru`, `ru-RU`, `ru-BY`, `ru-UA` |

The default language is `Lang::En` when no explicit configuration is provided.

---

## Available API

```rust
use runique::utils::trad::{set_lang, current_lang, t, tf, Lang};

// Set the global language
set_lang(Lang::Fr);

// Read the active language
let lang = current_lang(); // → Lang::Fr

// Translate a key
let msg = t("forms.error.required"); // → "This field is required"

// Translate a key with parameters (replaces {} with arguments)
let msg = tf("forms.error.too_short", &[3]); // → "Too short (min 3)"
```

| Function | Signature | Description |
| --- | --- | --- |
| `set_lang` | `fn set_lang(lang: Lang)` | Sets the global application language |
| `current_lang` | `fn current_lang() -> Lang` | Returns the active language (default: `En`) |
| `t` | `fn t(key: &str) -> Cow<'static, str>` | Translates a simple key |
| `tf` | `fn tf<T: Display>(key: &str, args: &[T]) -> String` | Translates a key with `{}` substitutions |

---

## Key format

A key is written `subject.section.key`. The subject is the name of the file, the section a part of that file.

```text
forms.error.required     → locales/<language>/forms.json   { "error": { "required": "…" } }
forms.hint.slug          → locales/<language>/forms.json   { "hint":  { "slug": "…" } }
admin.login.label.title  → locales/<language>/admin/login.json   { "label": { "title": "…" } }
```

The sections: `error` (a refusal or a failure), `label` (titles, buttons, labels), `hint` (a help), `log` (a log line), `info` (what just happened).

Each of Runique's keys has its constant, which follows the same path:

```rust
use runique::utils::trad::{keys, t, tf};

t(keys::forms::error::REQUIRED);            // "This field is required"
tf(keys::forms::error::TOO_SHORT, &[3]);    // "Too short (min 3)"
```

A misspelt constant doesn't compile. The `{}` in a text is replaced, in order, by the arguments given to `tf`.

---

## Fallback behaviour

For a key, Runique looks in this order:

1. the project's files for the language in use (see below);
2. Runique's files for that language;
3. the language that one falls back on, the same way, down to English;
4. if nothing has it, the key itself.

An incomplete translation therefore never causes a panic.

---

## The project's translations: the `locales/` folder

A project keeps its own translations in a `locales/` folder at its root, laid out as Runique's: one folder per language, one file per subject.

```text
my_project/locales/
├── fr/
│   ├── shop.json          ← a subject of the project
│   └── forms.json         ← messages of Runique rewritten
└── nl/                    ← a language Runique doesn't ship
    ├── lang.json
    └── forms.json
```

Runique reads this folder at start, the application as well as the `runique` command. No code to write.

**Translating your site.** A file that isn't named after one of Runique's subjects is a subject of the project:

```json
// locales/en/shop.json
{ "title": "Shop", "cart": { "empty": "Your cart is empty" } }
```

```rust
t("shop.title");
t("shop.cart.empty");
```

**Rewriting a message of Runique.** A file named after one of Runique's subjects, with the same key: the project's message comes first, for that language only.

```json
// locales/en/forms.json
{ "error": { "required": "Please fill this in" } }
```

**Adding a language.** A folder whose name isn't one of Runique's languages is a new one. Its name is its code, in lowercase (`nl`, `pt-br`). A `lang.json` file describes it:

```json
// locales/nl/lang.json
{ "name": "Nederlands", "aliases": ["nl-nl", "nl-be"], "fallback": "fr" }
```

| Field | Role | Without it |
|---|---|---|
| `name` | the name of the language | its code |
| `aliases` | the other ways to write it (`nl-be`) | none |
| `fallback` | the language to look in for a missing message | English |

A project's language doesn't have to translate everything: what is missing is shown in the language it falls back on. It is obtained by its code:

```rust
let dutch = Lang::from("nl");
```

**What Runique checks at start.**

| Case | What happens |
|---|---|
| an invalid JSON file, or a value that is neither a text nor a section | the start stops, with the name of the file |
| a folder whose name isn't a language code | the start stops |
| an unknown fallback language, or fallbacks going round in a circle | the start stops |
| two languages under the same code or alias | the start stops |
| a key Runique doesn't know in one of its subjects (`forms.error.requird`) | a warning in the log: almost always a typo |
| a message rewritten with another number of `{}` | a warning in the log |
| messages of Runique not translated in a new language | a summary by subject in the log |

The folder is kept elsewhere with `LOCALES_DIR` in the `.env`.

## Choosing the language

Through the `.env`, at the project root:

```ini
LANG=fr
```

or in `main.rs`, before building the app:

```rust
use runique::utils::trad::{set_lang, Lang};

set_lang(Lang::Fr);
```

A `set_lang` written in the code has the last word over the `.env`. Without either, the application is in English.

| | The application | The `runique` command |
|---|---|---|
| `LANG` of the `.env` | yes | yes, first |
| `LANG` of the system | no: a server's language isn't that of the site it serves | yes, next |
| `set_lang()` | yes, it has the last word | not applicable |

`LC_ALL` and `LC_MESSAGES` are read like `LANG`. A full value is understood: `fr_FR.UTF-8` is `fr`. A code nobody carries gives English.

The language is the same for every visitor.
